# 面证 · 现场演示步骤与口播脚本

适用：给评委/同事做 6 分钟左右的现场演示，或作为屏幕演示的旁白。**提交用的 3 分钟出镜视频不在这份里**（见 `docs/面证-笔试方案.md` §8.3）。
演示数据是一条「三天前跑完」的真实链路：定标、第一轮面试与面评、第二轮准备，外加两位候选人的不同状态。**全程只读，不现场重新跑 Agent**（重新跑会调真实模型，慢，还会改数据）。

---

## 一、演示前准备（一次性，约 2 分钟）

### 1. 生成一个干净的演示库

```bat
cd /d D:\wangyi
set MIANYAN_DB_PATH=data/demo-20261029.db
npm run seed
```

跑完屏幕上会打印库路径、账号、密码、岗位、面评与看板数字。核对三件事：

- 岗位「高级后端工程师」，金标准 7 个维度；
- 候选人 张伟 / 李娜 / 周航；
- 看板：24 小时内提交 **1/2**，可用面评 **1/2**。

> seed 只在空库上执行。若提示「已有工作区」，换一个文件名重新跑（不要删你原来的库）。

### 2. 启动（一个窗口就够，保持不关）

```bat
cd /d D:\wangyi
set MIANYAN_DB_PATH=data/demo-20261029.db

```

这一条会同时起后端（8787）和前端（5173），日志用颜色分开。浏览器打开 `http://localhost:5173`。

> 只有想分开看日志、或单独重启其中一个时，才开两个窗口分别跑 `npm run dev:server` 和 `npm run dev:web`；两个窗口都要先 `set` 同一个库路径。演示时不必。

## 二、六分钟演示脚本

时间按「口播 + 点击」估算，念快一点可在 5 分钟内讲完。

### 第 0 幕 · 开场（30 秒，停在登录页或「今天」）

> 我在上一个项目里做过一件事：不信任模型自报，只认能核对的结果。起因是一组数据——20,574 次真实会话里，22.58% 的问题是模型「误报完成」。
> 这个产品是同一条原则，用在面试上：让每个判断都有出处，把没问清的地方带到下一轮。
> 不筛简历、不当 AI 面试官，也不替人打分。
> 下面这条链路是三天前真实跑完的：一次定标、两轮面试、三份面评。三个角色各登录一次，从他们的视角看同一件事。

---

### 第 1 幕 · 定标：用人经理只来一次（60 秒）

**操作**：登录 `zhao@…` → 左侧「考察标准」。默认落在「双方签署定稿」；先点上面的 **「访谈（4 轮）」** 看它是怎么问的，再点 **「逐项确认（7/7）」** 看 7 个维度，最后回到 **「双方签署定稿」**。

**看什么**：四个阶段标签；访谈页左边是「这场访谈是怎么问的」、右边是「访谈记录（4 轮）」；确认页是 7 个维度；签署页是两栏签名。

> 用人经理每个岗位只来一次。他不需要填一张表，助手按他的回答决定下一个问题——他说到「大促压测」，下一个问题就问压测；说不到，就问取舍。
> 问完整理成 4 到 7 个维度，每个维度有三样东西：值得看的表现、需要警惕的信号、下一轮怎么追问。
> 这里有一个闸门：标准必须他和 HR 各签一栏才生效，一个人签不了两栏。

**手指停在**：签名区（「双方确认与定稿」）。

---

### 第 2 幕 · 赛前：先看缺口，再看简历（50 秒）

**操作**：退出登录 → 登录 `wang@…` →「一页纸准备」→ 在「选一场已经排好的面试」列表里点 **「张伟 · 高级后端工程师 · 第 2 轮 · 视频面」**。

**看什么**：左边是「这一页」（上方是生成记录），右边是「候选人的证据账本」和「追问提纲」；整页记录在「这一页纸是怎么来的」。

> 第二轮准备时，它做的第一件事不是读简历，是翻上一轮的账本：哪两维没拿到原话、哪一维被推翻。
> 这两维被排在一页纸最前面。上一轮没问清的，这一轮先问。
> 生成完它还会自查：每个维度有没有落点、问题是不是太多、缺口是不是排第一。不合格自己修，最多修两次。

---

### 第 3 幕 · 赛后：每个分都挂原话（70 秒）

**操作**：左侧「面评」→ 在列表里点 **「张伟 · 高级后端工程师 · 第 1 轮 · 视频面」**。

**看什么**：左边「面评工作台」是逐维草稿，下面是「这次面评是怎么查的」记录；右边是综合意见和「提交条件」。

> 面完，它按维度去转写里找原话：先查哪个维度、用哪组词，是模型自己排的。
> 找到就起草，每条引用都要回原文核对时间和句子，对不上就换词重搜；三组词都找不到，就把这一维标成缺口，不编。
> 注意这一屏的分数：草稿里是模型起的评分，但矩阵不认它。要面试官自己逐条改分、写一句推荐、勾同意，才能提交。

**点一下**：展开任意一维的引用（或指一下「有原话 N 段」）。

---

### 第 4 幕 · 结果：并排、看图、看缺口、点开原话（90 秒，这次新做的屏）

**操作**：退出登录 → 登录 `hr@…` →「候选人结果」。默认选中的是张伟；先讲完表格，再点表格上方 **「李娜」**，右边换成她的图。

**看什么**：左边表格（7 维 × 3 人），右边选中者的矩阵图和「还缺哪几维」。

> 这是 HR 要给这个岗位一个说法时看的一屏。
> 左边把三个人放在同一把标准下并排：每一格是一个维度落在哪、挂了几句原话。
> 右边是选中那个人的形状。形状只连「评过、并且挂了原话」的维度——李娜有一维凭印象打了分，但一句原话都没留，所以在图上是空心圈，不进形状；没评的干脆不画点。
> 缺口就摆在图下面：她还有四维没终评、一维没原话。
> **点开任意一维**，能看到面试官当时挂的那几句原话和它在转写里的位置。（点「数据驱动」演示）
> 这里不排名、不给总分：排序等于把录用建议换了个说法，会让面试官为了让分好看去凑证据。

**若有人问为什么三个人里只有一个形状完整**：因为另外两个人一个只交了一半、一个还没面——这正是要暴露的，不是要藏起来的。

---

### 第 5 幕 · 交付看板：两个数，不是一个（40 秒）

**操作**：左侧「交付看板」。

**看什么**：顶部四个数——待提交、已交面评、已标记失效、24 小时可用面评率；第四个数下面一行小字写着「1/2 份按时，其中 1 份每个维度都有落点」。

> 这两个口径不是一个意思。小字里前半句只看交没交，后半句还要求每个维度都有落点、结论挂得回原话、推荐意见是人写的。
> 今天是 1/2 份按时、其中 1 份可用：张伟那份当场交、5 维有原话、2 维登记成缺口，算；李娜拖到第 30 小时，还有一维没挂原话，两个口径都没算她。
> 我们宁可显示 50%，也不把「交了」算成「可用」。

---

### 第 6 幕 · 收尾（30 秒）

> 这一版的边界很清楚：做到「面评交上来」为止。谁去决定录用、怎么排优先级，不在这一版里，也不该由一个模型来定。
> 不做实时提示、不做自动评分、不做简历筛选，也不做候选人排名。
> 一句话：模型提议，代码核对，人拍板。

## 三、可能被问到的问题（照着答）

| 问题 | 答 |
|---|---|
| 图用了什么图表库？ | 没有。手写 SVG，三种状态（实心 / 空心 / 不画）自己控制；前端唯一依赖是图标库。 |
| 为什么没有总分和排名？ | 总分和排序就是自动化录用建议，锚定人、责任稀释，还会诱导面试官凑证据；我们只并排，结论留给人。 |
| AI 会不会编原话？ | 每条引用都要回原文核对句子和时间戳，对不上换词重搜；找不到就标缺口，草稿可以带着缺口交，但不能编。 |
| 和钉钉听记、飞书妙记有什么不同？ | 不跟它们拼转写，直接导入它们的转写；我们加的是岗位标准、每条结论必须挂原话的闸门、跨轮接力和交付清单。 |
| 数据是真的吗？ | 演示库是本地固定时钟 + 模拟模型跑出来的，用来展示状态；真实模型链路跑通过，但没有做过客户试点，方案里写了验证计划。 |
| 为什么用人经理只有一个画面？ | 调研里他每个岗位只登录一次，所以只做定标；再给他开一个决策会流程，就是第四个功能，V1 不做。 |

## 四、现场卡住了怎么办

- **登录不了**：确认启动前那个窗口里 `set` 的是第 1 步生成的库；换了库名就重跑第 1 步。
- **候选人结果只有一个人**：seed 跑的是旧库或旧版本代码，重跑第 1 步。
- **Agent 记录空白**：演示数据里三份记录都是 seed 时真实跑出来的；若被清空，重新 seed，不要在台上点「重新生成」。
- **网络/模型慢**：全程不需要外网，也不需要模型 key；演示只读。
- **兜底**：本地 `.tsbuild/qa2-1-desktop.png`、`qa2-2b-quotes.png`、`qa2-4-mobile.png` 是这屏的实拍截图，可临时顶上。

## 五、视频怎么录（两种，别混）

**提交用的那支（作业要求）**：3 分钟以内、出镜、真人口述、不念稿，讲自我介绍 + 作业思路。提纲和每段时间见 `docs/面证-笔试方案.md` §8.3。这份 6 分钟脚本**不是**提交视频的稿子，别照着念。

**屏幕演示（可选）**：如果要另录一支走界面的，按本文件第 1–6 幕走，系统录屏或 OBS，1280×800 以上，全程只读；每幕之间停 1 秒，不加转场。
