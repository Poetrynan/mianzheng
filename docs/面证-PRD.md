## 三、文档说明

| 术语 | 说明 |
|---|---|
| 金标准（考察标准） | 用人经理与 HR 双签后生效的维度集合，4–7 条，每条含可观察表现、警惕信号、追问建议、匹配关键词 |
| 一页纸 | 赛前给面试官的一页：关键信息、维度对齐、3–6 个追问、红旗、上一轮缺口 |
| 面评草稿 | Agent 按维度起草的判断与原话引用，需面试官逐条确认/改分后提交 |
| 终评 | 面试官在提交版里落下的 `finalScore`；矩阵只认它 |
| 原话 / 证据 | 转写中的候选人发言片段，带 `segmentId`、`startMs`、`quote` |
| 缺口 | 维度没有终评，或有终评但一条原话都没挂 |
| 证据账本 | 一人 × 一岗 × 一维度的状态表（已覆盖 / 没有原话 / 没打分 / 有矛盾），只由已提交面评更新 |
| 可用面评 | 24h 内提交，且每维有落点（终评或登记缺口）、评分结论挂得回原话、推荐意见是人写的 |
| 三轮检索 | 每个维度最多三组关键词；三组都无命中即标缺口 |
| 步数预算 | 定标 32 / 赛前 16 / 赛后 44，硬上限 120；同一动作连续 3 次即停 |

## 四、需求背景

### 4.1 产品现状与核心问题

- **产品现状**：会议软件（钉钉听记、飞书妙记）已能免费转写并按模板生成面评；Moka Eva、北森等 ATS 把纪要、回填、实时追问打包进流程。再做「把录音变成面评」没有差异化。
- **核心问题**：面试结束到录用决定之间，**没有一份可核对、可比较、能接力的评估**。
  - 不可核对：结论是自由文本，回不到原话；
  - 不可比较：每场一份、标准各异；
  - 不可接力：下一轮看不到上一轮哪里没问清。
- **北极星指标**：**24 小时可用面评率**（定义见 §12.2）。它同时约束「快」和「能用」，而不是「交了」。

### 4.2 调研方法与结论（证据分级）

**方法**：桌面研究（论文、厂商官网/案例、公开调查、从业者自述）；**没有做一手访谈、没有做问卷**。所有数字按 A/B/C/D 分级，C 级（厂商自述）只当线索。

| 结论 | 证据 | 等级 |
|---|---|---|
| 面评拖延的根因是「写起来贵」而不是「忘」：厂商调查中 75% 的面试官愿意写，但一份要 20–30 分钟 | Moka 公开案例；从业者自述 | C / B |
| 结构化面试效度约 .42，非结构化约 .19 | Sackett 等 2022, *JAP* | A |
| 面评回收率普遍在 40% 上下，延迟 3–5 天，23% 的反馈在候选人进入下一轮时仍未提交 | 厂商/行业调研，待试点复核 | C |
| 面试官人均低频：400 人公司、80 名兼职面试官、年招 120 人，人均一年 8–11 场 | 本文推算 | D |
| 「AI 帮我打分/录用」是假需求：责任、锚定、合规三问题 | 访谈归纳与合规分析 | — |

> **必须声明的局限**：方案 §1.1 的人物画像是「依据公开资料归纳的虚构画像」，仓库里没有一手访谈记录；所有 C 级数字都要在试点第一周自测校准。

### 4.3 竞品与空位

| 竞品 | 已做到 | 空档 |
|---|---|---|
| 钉钉 AI 听记 / 飞书妙记 | 免费转写、面试报告模板、妙记问答写面评 | 不按岗位标准；结论不可逐条核对；一场一份 |
| 飞书招聘 / 北森 / Moka Eva | 题库、提醒、自动回填、实时追问 | 标准来自通用题库或历史数据；结论是「总结」不是「证据」；跨轮断掉 |
| Metaview / BrightHire | 英文市场，纪要 + 评分卡回填 | 国内不可用；同样不做定标与跨轮 |

**空位**：① 标准从用人经理嘴里来；② 每条结论回到原话；③ 缺口跨轮接力。这三点是 V1 的差异化，其余（交付清单）是附带价值。

## 五、用户与场景

| 角色 | 何时登录 | 要什么 | 本版给什么 |
|---|---|---|---|
| 业务面试官（每场必用） | 赛前一次、赛后一次 | 5 分钟知道这轮验什么；面完不用写作文 | 一页纸；逐维挂好原话的草稿，改分即交 |
| 招聘 HR（付费方） | 每天 | 谁还没交；这个岗位现在能不能给人一个说法 | 交付看板；候选人结果；待提交清单 |
| 用人经理（价值锚） | 每个岗位一次 | 标准说清楚、落到每一场 | 30 分钟定标访谈；双签；之后不再登录 |
| 候选人（不使用） | 不登录 | 被尊重、被告知、可拒绝 | 单独同意、拒绝不影响、删除走 HR 代办 |

**产品边界**：做到「面评提交」为止；录用决定与委员会流程不进入本版。

## 七、核心流程

### 7.1 人和 Agent 的分工

| 步骤 | 谁 | Agent | 人 | 失败路径 | 留痕 |
|---|---|---|---|---|---|
| 建岗 | HR | 无 | 填岗位信息 | — | 岗位记录 |
| 定标 | Agent + 经理 + HR | 按缺口提问、整理 4–7 维、步数不足收手、两次整理失败停 | 经理逐条确认并签；HR 审合规并签 | 急招走快启；签不齐不生效 | 版本、签署人、每轮问答 |
| 录简历/排期 | HR | 解析简历 | 确认候选人、时间 | 解析失败手填 | 候选人记录 |
| 生成一页纸 | Agent | 读账本 + 简历，生成页；自检最多修两次 | 增删问题；HR 否决风险问题 | 修不好停下交人 | 版本、带过的缺口、自检结果 |
| 同意 | 候选人 | 无 | 同意/拒绝 | 拒绝 → 手动评分 | 版本、时间 |
| 面试 | 人 + 会议软件 | 无 | 正常面试 | 撤回 → 停止记录并删除 | 状态 |
| 导入转写 | Agent + 面试官 | 识别发言人 | 指认候选人 | 认不出 → 通用格式；拒绝过 → 拒绝导入 | 来源、段数 |
| 起草面评 | Agent | 逐维检索、核对、重试、标缺口 | 无 | 证据不足 → 标注；三组无 → 缺口 | 每步检索与核对 |
| 改分/提交 | 无 | 无 | 逐项确认、改分、写推荐、提交 | 不交 → 24h 一次提醒 | 修改记录 |
| 清单 | 无 | 无 | HR 看清单、提醒 | 超 24h 进清单，不升级 | 提醒记录 |

### 7.2 主流程（一条真实链路）

```
HR 建岗 → 用人经理定标（Agent 访谈 4 轮）→ 双签 → HR 排期
→ 面试官打开一页纸 → 候选人同意 → 面试（会议软件转写）
→ 面试官导入转写并指认候选人 → Agent 逐维检索/核对/起草
→ 面试官改分、写推荐、提交 → 账本更新
→ HR 看板看交付、看候选人结果 → 下一轮一页纸优先补缺口
```

### 7.3 异常流程

| 场景 | 处理 | 不能做 |
|---|---|---|
| 候选人拒绝记录 | 正常面试，一页纸 + 手动评分 | 拒绝后仍导入/扣分 |
| 会议无转写 | 本机录音兜底；都没有转手动 | 假装有记录 |
| 转写格式认不出 | 回退通用格式，人工指认发言人 | 猜错候选人 |
| 三组词都找不到 | 标缺口，写明检索词 | 补分、用印象填空 |
| 步数将尽 | 未查维度标缺口，先保草稿 | 静默失败 |
| 同一动作重复 3 次 | 停止并说明原因 | 继续空转 |
| 两次整理不出维度 | 停下交人 | 硬凑维度 |
| 标准未双签 | 一页纸/面评不可用 | 用未生效标准 |
| 未登录/越权 | 401 / 404 | 泄露其他工作区数据 |
| 提交含未评分维度 | 允许确认缺口后提交 | 静默当成已评 |

## 八、功能详细说明

### 8.1 定标（考察标准）

**需求描述**：用 30 分钟访谈把用人经理脑子里的标准问成 4–7 个可观察维度，逐条确认后由用人经理与 HR 双签生效。

**流程**：选岗位 → 开始访谈 → Agent 一问一答（问题跟着回答走）→ 整理维度 → 逐项确认（可编辑）→ 双方签署 → 定稿生效。

**页面与字段**

| 元素 | 类型 | 规则 |
|---|---|---|
| 岗位 | 下拉 | 必选；显示是否已定稿 |
| 本次最想弄清的问题 | 文本 | 选填，≤200 字 |
| 维度名 | 文本 | 必填，≤20 字 |
| 值得看的表现 / 警惕信号 / 追问建议 | 多行文本 | 各至少 1 条 |
| 匹配关键词 | 文本 | 逗号/顿号分隔，≥1 个 |
| 确认 / 签署 | 按钮 | 用人经理签 `hiring_manager`，HR 签 `hr`；服务端校验角色 |

**异常**：步数将尽先交草稿；两次整理失败停下；冲突维度由 HR 选择保留标准或改写；未双签不得生效。

**验收标准**
- [ ] 未双签时，一页纸与面评入口提示「标准未生效」，不可生成。
- [ ] 同一账号不能同时签两栏（服务端 403）。
- [ ] 维度数目标 4–7；少于 3 条时，候选人结果页提示画不成矩阵。
- [ ] 每个维度的四类信息齐全才允许确认。
- [ ] 定稿后版本号 +1，历史版本可查签署人与时间。

### 8.2 一页纸（赛前）

**需求描述**：面试前给面试官一页，说明这轮验什么、上一轮哪里没问清。

**流程**：选面试 → 读账本（只取已提交面评的开放缺口）→ 生成 → 自检（落点/问题数/合规/缺口置顶）→ 面试官增删 → 赛前阅读。

**规则**：追问 3–6 个；二面起缺口排最前；自检最多修 2 次；候选人拒绝记录时不生成录音相关提示。

**验收标准**
- [ ] 二面的一页纸里，上一轮缺口出现在第一条追问之前。
- [ ] 自检不通过最多修 2 次，之后停下并显示原因。
- [ ] 未提交的草稿不进入账本，不出现在下一轮。
- [ ] 问题数超出 3–6 时自检失败并可修。

### 8.3 面评（赛后）

**需求描述**：把一场面试整理成「每个维度有结论、每个结论有原话」的草稿，由面试官改分并提交。

**Agent 行为**：按模型排的调查计划逐维检索；只搜候选人发言；引用回原文核对（句子 + 时间戳）；对不上换词重搜；每维最多 3 组词；换词不丢已找到原话；步数不足先保草稿并标缺口；最后问人「缺口带不带下一轮」。

**人工闸门**：逐条确认/改分；写综合推荐；勾选「同意作为决策依据」；提交。

**页面与字段**

| 元素 | 类型 | 规则 |
|---|---|---|
| 评分 | 三档（达标/部分达标/不达标） | 人选择；可留空 |
| 结论摘要 | 文本 | 人可改；≤500 字 |
| 原话 | 引用列表 | 来自转写，可增删；显示时间码 |
| 综合推荐 | 多行文本 | 必填，人写 |
| 提交 | 按钮 | 未填维度需确认「带缺口提交」 |

**验收标准**
- [ ] AI 起评分不进入候选人结果矩阵；矩阵只读 `finalScore`。
- [ ] 每条保留的引用都能在转写里逐字找到；对不上的被剔除并可见。
- [ ] 三组词无命中时，该维标缺口且不生成结论。
- [ ] 没写推荐意见或仍有维度没评时，提交必须显式确认缺口；这份面评不计入「可用」。
- [ ] 提交后账本更新，重复提交被拒绝。

### 8.4 证据账本

**规则**：一人 × 一岗 × 一维一行；只由已提交面评更新；状态四类（已覆盖 / 没有原话 / 没打分 / 有矛盾）；下一轮赛前读取开放缺口。

**验收标准**
- [ ] 未提交草稿不写账本。
- [ ] 后一轮结论覆盖前一轮，但保留轮次与提交人。
- [ ] 矛盾结论标「有矛盾」，不静默覆盖。

### 8.5 交付看板（HR）

**指标**：待提交、已交面评、已标记失效、24 小时可用面评率；列表灯只反映交付，不反映候选人表现；24h 一次提醒；周报可复制。

**验收标准**
- [ ] 「已交」与「可用」分开计算；可用率分母含到期未交。
- [ ] 提醒只发一次，不做 0/24/48/72 升级。
- [ ] 灯为灰/黄/红/绿四态，且与候选人评分无关。

### 8.6 候选人结果（HR）

**规则**：轴 = 已定稿标准的维度；值 = 提交版 `finalScore`；形状只连「有终评且有原话」的维度；有判断无原话画空心圈、不进形状；没评不画点；并排表不排名；点开任一维显示原话与时间码。

**验收标准**
- [ ] 无原话的维度显示空心圈，且不进多边形。
- [ ] 未提交面评的候选人在表中显示「还没交」，不参与缺口统计。
- [ ] 页面不出现排序、总分、推荐录用。
- [ ] 点开维度能看到该维原话；空维度点开为空且说明原因。

### 8.7 现场记录与导入

**规则**：候选人单独同意后才可导入；支持钉钉听记、飞书妙记、腾讯会议与通用格式；必须指认候选人；撤回同意即停止并删除；本机录音为兜底。

**验收标准**
- [ ] 未指认候选人不能导入。
- [ ] 候选人拒绝过的面试，导入入口禁用。
- [ ] 撤回后不再写入新片段。

### 8.8 隐私与记录

**规则**：同意版本/时间/操作人留痕；录音与转写 180 天、同意记录 730 天；删除由 HR 代办并留痕；AI 内容显著标注；审计可查。

**验收标准**
- [ ] 同意与拒绝同等权重，拒绝不影响流程。
- [ ] 删除操作产生审计记录。
- [ ] 到期数据可被清理任务识别。

### 8.9 登录与账号

**规则**：邮箱 + 口令；口令 scrypt 散列；会话令牌只存 SHA-256；HttpOnly Cookie 14 天；同一邮箱连错 8 次锁 15 分钟；改密后所有设备失效；跨工作区读写返回 404。

**验收标准**
- [ ] 无会话访问业务接口返回 401。
- [ ] 改密后旧令牌全部失效（测试覆盖）。
- [ ] 越权读取他组织数据返回 404。

## 九、AI 能力定义

### 9.1 任务类型

Agent（目标 + 循环 + 工具 + 自检 + 跨轮记忆），内含：维度整理（生成/结构化）、检索计划（推理）、引用核对（规则 + 检索）、草稿（生成）。

### 9.2 输入 / 输出

- 输入：岗位信息、维度定义与匹配关键词、候选人简历、转写片段（含发言人/时间戳）、账本缺口、步数预算。
- 输出：维度草稿（score/summary/segmentIds/redFlags/needsHumanInput）、一页纸（关键信息/对齐表/追问/红旗/自检）、调查计划（维度顺序 + 每组 2–3 个检索词 + 理由）。
- 上下文：单场转写通常 10–60 段；不引入向量库，关键词检索 + 逐字核对。

### 9.3 技术链路

```
[岗位/简历/转写/账本]
      ↓
[计划] 模型排序维度 + 选检索词（代码校验：维度存在、词 2–24 字、去重、每维≤3 组）
      ↓
[检索] 关键词命中候选人发言（代码）
      ↓
[起草] 只喂该维定义 + 命中片段（模型，无工具调用权）
      ↓
[核对] 引用逐字 + 时间戳回原文（确定性代码；不过则剔除并记失败）
      ↓
[重试] 换下一组词（最多 3 组；已读原话不丢）
      ↓
[缺口] 仍无 → 标「证据不足」，写明检索词
      ↓
[合成] 草稿 + 自检 + 问人「缺口带不带下一轮」
      ↓
[人] 改分 / 写推荐 / 提交 → 账本更新
```

### 9.4 模型与配置

- 主模型：任意 OpenAI 兼容 `/chat/completions`（默认 LongCat，可通过 `MIANYAN_LLM_*` 切换）。
- 草稿模型无工具调用权；不能触发检索、提交、改分。
- 超时默认 90–120s；失败重试与降级策略见 9.6。

### 9.5 评测

| 维度 | 方法 | 目标 |
|---|---|---|
| 引用准确率 | 核对保留 / 模型提出 | ≥95% |
| 换词重试成功率 | 第一组无命中后后续命中的维度占比 | ≥50% |
| 缺口识别 | 负样本（确实无原话）不得给结论 | 100% |
| 任务完成率 | 走到完成态 / 启动 | ≥90% |
| 非设计内接管 | 步数耗尽/重复/自检失败/放弃重跑 | ≤20% |
| 步骤同质化 | 完全相同的步骤序列占比 | ≤90% |
| 成本 | 单场 LLM + 存储 | <¥3 |

**离线验证**：117 个自动化测试（8 个文件），含 10 个负样本与「AI 起评分不进矩阵」的断言。**尚无真实试点数据。**

### 9.6 兜底

| 场景 | 处理 |
|---|---|
| 模型计划失败/为空 | 按标准关键词兜底继续 |
| 引用核对失败 | 剔除该条，记失败步骤 |
| 三组词无命中 | 标缺口，不补分 |
| 步数不足 | 未查维度标缺口，先保草稿 |
| 重复动作 3 次 | 停止并写明原因 |
| 低置信片段 | 标注，提示人工补 |
| 提示注入（转写里出现指令） | 草稿模型无工具权；引用仍逐字核对 |

## 十一、非功能需求

- **性能**：看板/结果接口 P95 < 500ms（本地库，1 万段以内）；Agent 单场 < 2 分钟（目标，未在真实转写验证）。
- **安全**：口令 scrypt、会话服务端存储、HttpOnly Cookie、跨组织 404、审计；未做渗透测试，不宣称生产级安全。
- **合规**：单独同意、目的限定、最小必要、保留期、删除、AI 标识、自动化决策影响评估（不自动决策）。
- **兼容**：Chrome/Edge 最新两个大版本；1280px 与 430px 两档验收；无横向溢出。
- **成本**：单场 <¥3；按 run 记录 token 与费用（待接入账单口径）。
- **可观测**：Agent 每步可回放；失败步骤可见；审计日志可查。

## 十二、埋点与指标

> V1 没有第三方分析 SDK；以下事件先落审计/任务记录，后续接入时按同名上报。

### 12.1 事件

| 事件 | 触发 | 关键参数 |
|---|---|---|
| standard_interview_started | 开始定标 | jobId |
| standard_signed | 双签完成 | standardId, version |
| prep_generated | 一页纸生成 | interviewId, round, carryOverCount |
| prep_opened | 赛前打开 | interviewId, seconds |
| transcript_imported | 导入转写 | source, segments |
| draft_generated | 草稿完成 | interviewId, evidenceCount, gapCount |

| gap_carried | 缺口带入下一轮 | dimensionId, toInterviewId |
| board_reminder_sent | 一次提醒 | interviewId |
| results_viewed | 打开候选人结果 | jobId, candidates |
| dimension_evidence_opened | 点开某维原话 | dimensionId |

### 12.2 指标定义

```
24h 可用面评率 =
  满足以下全部条件的已提交面评数
  / 24h 窗口已关闭的面试数
条件：
  ① submittedAt - endedAt ≤ 24h
  ② 每个维度有落点：有 finalScore，或已登记为缺口
  ③ 至少一个维度有终评，且其结论挂得回原话
  ④ humanRecommendation 非空
```

其他：缺口跨轮带过率、换词重试成功率、引用核对通过率、原样提交率、写面评用时、一页纸打开率、候选人同意率。
